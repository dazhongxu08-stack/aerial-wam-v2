# Tello 真机：后果模型后训练采集标准

**用途**：采 Tello 数据，微调已经在仿真里训好的后果模型（hazard / dgoal），供关罩真机部署。  
**不是**：城市场景仿真专家集、PathExpert、DepthSceneExpert、WAM 的 RGB+IMU schema-v2 入库。

落点：`artifacts/tello_gs/run_YYYYMMDD_HHMMSS/`。分析结论必须写「链路可用 / 域差可用 / 后训练可用」三档之一，禁止用转换脚本的 `usable` 计数代替本标准。

---

## 1. 模型要什么

后果模型一步的监督是：

| 字段 | 从哪来 | 没有会怎样 |
|------|--------|------------|
| `depth` | RGB 事后跑 DA3 可以 | 花屏/全黑帧丢掉 |
| `goal` | 每条起飞前写入 `meta.json` | `dgoal` 标不出 |
| 动作序列 | 遥测 `rc`（当时真正发给电机的命令，人手或自动都行） | 学不到「这么飞会怎样」 |
| `hit` | 空中碰撞或明确近撞 | 全 0 会把模型教成永远安全 |
| `dgoal` | 相对目标的远近变化 | 不要用 Tello 积分 `x/y` 当真实航迹 |

缺 `goal`、缺近障/碰撞、或记下的 `rc` 不是当时真正发出去的命令，整条不能后训练。

---

## 2. 可以自动飞，不要打实杆

**推荐自动采。** BADGR / ProbColl 也是策略自己飞、事后标碰撞。后训练要对齐部署，最好用关罩后果模型（或同动作空间的探索策略）自己飞，记下它发出的 `rc`。`control_mode=auto` 完全合法。

人手打杆也可以，只是备选：场景不好布置、或自动策略还不敢近障时用。人手不是硬性要求。

自动飞必须同时做到：

- 记下的 `rc` 就是发给 Tello 的那一组（auto 源），不要一边 auto 飞一边指望 H12 杆量进数据集。
- 有目标（§3.4），会朝目标走，会在障碍前停或转。
- 动作空间仍是悬停、原地转向、小幅前进；不要后退；不要飞鼻子左右 35° 以外的侧飞。
- 有效空中 60–120 秒，每条至少 3 次近障，一批里要有近撞/轻碰（§3、§4）。
- 安全门：高度 0.8–1.5 m、电量、RSSI、人靠近就停；撞上立刻停杆并停录。

**禁止的是写死示教程序，不是禁止自动。**  
`experiments/aerial/scripts/tello_mac_auto_collect.py` 的 `yaw_fwd` / `fwd_yaw` / `creep_yaw` 是固定时间轴打固定杆（前进 16–22、偏航 ±28、油门 18），每条约 25–35 秒、不看画面、不写目标。这是手写「先转后冲」的自动版，不能用来后训练。2026-10-12 下午室内那批（`run_20261012_164*`、`171802`–`172727`）就是它采的，全部不合格。

不要新写另一套「转 4 秒再前进 3.5 秒」的脚本。自动策略必须根据当前深度/画面做决定。

---

## 3. 单条必须同时满足

1. **场景**：室内或有墙的走廊/房间。障碍要进画面（墙、桌、椅、门框）。不要空地、停车场巡航、大面积天空、海边。这是 Tello 室内绕障，不必是仿真城市场景内部路线；也 **不得** 写进仿真专家集。
2. **高度**：空中稳定 **0.8–1.5 m**，占空中时间 **≥70%**。无净爬升，除非目标高 1 m 以上；无净下降，除非目标低 1 m 以上。近地 `h` 会跳成负数，降落前后几秒标注丢掉。
3. **时长**：有效空中 **60–120 秒**。落地立刻停录，不要录翻倒、手拿、侧躺还在打杆。
4. **目标**：起飞前定一个目标（门口、对面墙、桌子另一侧），写入 `meta.json`（见 §6）。没有目标就没有 `dgoal`。
5. **近障**：每条至少 **3 次**「再近一点就会撞」——障碍占满画面、前方空隙小，然后停或转走。允许轻碰后立刻停。在 2–3 m 外看一眼桌子不算。
6. **碰撞标签**：轻碰、急停、`emergency`（仅当空中撞上障碍）写入 `events.jsonl`，带时间。落地翻倒、降落失败后的侧躺 **不算** 飞行碰撞。
7. **记录完整**：JPEG + `telemetry.jsonl` + `events.jsonl` + `trajectory.csv` + `meta.json`。遥测要有 `rc`、`h`、`yaw`、`vgx/vgy`、`bat`、`wifi`、`frame_seq`、`control_mode`（`auto` 或 `manual` 均可，须与真正发杆的那一端一致）。电量不要飞到 20% 以下。
8. **画面**：给 DA3 的帧不能花屏、全黑。Wi-Fi RSSI 建议好于 −70 dBm。

---

## 4. 一批何时算够

先 **6–10 条** 单条合格的近障片段，再谈后训练。其中至少 **2 条**含轻碰或明确近撞，其余可以是安全躲开。不要全是 `hit=0`。

---

## 5. 三档判定（分析时必须用）

| 档 | 条件 | 能否进 `train_consequence` |
|----|------|---------------------------|
| 链路可用 | 图和遥测对齐、能起飞降落 | 否 |
| 域差可用 | 室内近障干净帧，可抽去跑 DA3 | 否 |
| **后训练可用** | §3 全部满足，且本批达到 §4 | 可以（丢掉降落前后坏段和花屏） |

`artifacts/tello_gs_npz/QUALITY_SUMMARY.json` 的 `usable` 是另一套 RGB+IMU 入库检查（画面有变化、有加速度计），**不能**当作本标准通过。

转换 npz 若没有 `goal`、没有深度、`rewards` 全 0、几乎没有 `collided`，即使 `quarantined=0` 也不能训后果模型。

---

## 6. `meta.json` 每条必填

在录像目录的 `meta.json` 里追加（不要丢掉原有 `run_id` / `started_at`）：

```json
{
  "goal_desc": "房间对面的门框",
  "goal_approx_m": 4.0,
  "goal_bearing_deg": 0,
  "control": "auto",
  "intended_use": "consequence_posttrain",
  "near_miss_n": 3,
  "collision_n": 0
}
```

`goal_approx_m` / `goal_bearing_deg` 相对起飞点粗估即可。禁止用积分轨迹当真实位移去算 `dgoal`（Tello `vgx/vgy` 是 dm/s 整数，会漂）。

近撞/轻碰同时在 `events.jsonl` 写一行，例如：

```json
{"t_s": 41.2, "event": "near_miss", "note": "desk edge, stopped"}
{"t_s": 67.8, "event": "collision", "note": "chair back, light tap"}
```

## 8. 采的时候怎么飞（现场清单）

**优先：关罩后果模型（或同动作空间的探索策略）自动飞。**

1. 地面站 `control_mode=auto`，确认 `allow_fly`，电量 ≥40%。H12 只作急停，不进数据集。
2. 写下目标（门 / 墙 / 桌另一侧），填进 `meta.json`，并交给规划器。
3. 开始录像 → 起飞 → 高度约 1 m。
4. 策略自己朝目标走；人只在要撞家具/人时接手或急停。每条至少 3 次近障。允许轻碰。
5. 有效空中满 1 分钟后再降落。
6. 落地立刻停录，停杆。
7. 下一条换目标方位或换障碍。不要循环同一段固定时间轴。

人手备选：把第 1 步改成 `manual`，第 4 步自己贴障停/转，其余相同。

安全：室内有人时不要贴人飞；不要为了标 `hit` 故意高速砸家具。轻碰即可。自动飞必须能随时 `emergency`。

## 9. 和仿真专家采集的边界

城市场景内部规则（`in_interior`、岸线距离、`AUTO_REVIEW`）只约束 **AirSim 专家 / 演示数据**。Tello 室内后训练不套那条地理规则，但也不得把 Tello 片段写进仿真专家集。
